# CAS External Radar — Rust 1.0

Переписанный на **Rust** сервер и считыватель данных из `CAS External Radar v0.8`. В пакете **нет Python**, DLL-инжекции, драйверов, WinAPI-записей в память игры или механизма обхода античита. HTML/CSS/JS-интерфейс из v0.8 оставлен без смены фреймворка. **Добавлен отдельный мини-радар Windows, который является обычным нативным окном Rust/Win32/GDI+, а не браузерным окном/WebView.**

## Если карта есть, а игроков нет

Название карты может приходить через GSI независимо от чтения игроков. При
ошибке `dwEntityList` радар различает пустой список и отказ чтения памяти, а DIAG
сохраняет код Win32, счётчики чтения и версии офсетов/игры.

Если глобальные адреса устарели, радар пробует восстановить адрес списка и
локального контроллера по сигнатурам a2x/cs2-dumper в исполняемых секциях
`client.dll`. Адреса применяются только после проверки связи контроллера со
списком сущностей; изменения действуют только для текущего процесса и не
перезаписывают кэш JSON. При неудаче попытка повторяется не чаще раза в 30 секунд.
Сигнатуры тоже могут измениться после обновления игры: тогда требуется свежая
выгрузка офсетов, а не показ выдуманных игроков. Отказ доступа к памяти таким
восстановлением не обходится. Для дальнейшей диагностики используйте DIAG.

## Определение карты и таймер C4

Если карта не определилась, радар показывает это явно: Mirage не подставляется.
Выберите **Nuke** в списке основной карты — выбор применяется и к мини-карте.
Кнопка **AUTO** возвращает автоматическое определение. Ручной выбор действует
до закрытия сервера радара. На основной карте этаж выбирается отдельно; мини-карта
переключает верхний/нижний этаж Nuke по высоте локального или наблюдаемого игрока.

Последняя подтверждённая карта сохраняется при пропуске GSI-сигналов; автоматический
выбор очищается при подтверждённом закрытии CS2. Восстановление адресов обновляет
также доступные глобальные адреса карты, часов и C4. Таймер C4 поддерживает прямой
указатель и контейнер указателя, использует реальное игровое время и скрывается
после разминирования/взрыва. Таймер не зависит от наличия фона карты.

Повреждённый PNG в кэше заново загружается при доступном интернете. `--refresh`
также обновляет фон при следующем запросе; без флага действующий PNG проверяется
на обновления через 24 часа. При сбое загрузки рабочая копия сохраняется. Загрузка фона
мини-карты идёт отдельно от оконного потока; при ошибке выводится сообщение.

## Карта и мини-радар: информация об игроках

- На обеих картах рядом с противником показываются **ХП**, активное оружие и
  стрелка **↑ / ↓**, если он выше / ниже вас более чем на 64 игровых единицы.
  На одной высоте стрелки нет. В спектаторе высота сравнивается с наблюдаемым
  игроком; если его положение неизвестно, стрелок нет.
- Белые перекрещенные стрелки на маркере означают ослепление, подтверждённое
  текущими игровыми данными. Неизвестное состояние не выдаётся за ослепление.
- В центре активного смока / огня — оставшееся время в секундах. Знак **~**
  означает оценку с первого обнаружения, если время начала эффекта не прочитано.
- Карточки команд постоянно показывают полный прочитанный инвентарь и броню,
  шлем, набор сапёра, деньги и ХП. Повторные гранаты не скрываются. Портрет
  подбирается по модели агента и загружается со Steam CDN; при отсутствии
  изображения отображается нейтральный силуэт, а не выдуманная аватарка.
- Мини-радар открывается без стандартного заголовка Windows: перетаскивайте
  верхнюю полосу, меняйте размер за края, закрывайте **×** или **Esc**.
  Повторно открыть окно можно в настройках основной карты.
- Масштаб миникарты: **0.35–4×**, по умолчанию **1×**. Сохранённый ранее масштаб
  остаётся действующим. Дальние игроки отмечаются у края с указателем направления
  и подписью «ДАЛЕКО». Кнопки **− / +** или колесо меняют масштаб.

Отображаются только доступные клиенту данные: увеличение охвата миникарты не
создаёт информацию о противниках, которую сервер игры не передал клиенту.

## Готовый Windows EXE через GitHub Actions / Releases

Для запуска опубликованного релиза **не нужны Rust, cargo, Visual Studio или link.exe**. Рекомендуемый способ — скачать `CAS-Radar-Windows-x64.zip` из GitHub Releases, распаковать и запустить `start_windows.bat` или `cas-external-radar.exe`. Отдельный `.exe` тоже публикуется и может работать без папки `web`, потому что HTML встроен в бинарник; ZIP дополнительно включает README и отдельный веб-интерфейс.

### Первая публикация репозитория

Нужны только [Git for Windows](https://git-scm.com/downloads/win) и [GitHub CLI](https://cli.github.com/). В распакованной папке запусти `publish_to_github.bat`. При первом запуске `gh auth login` предложит выполнить вход в GitHub через браузер.

Репозиторий уже создан: `frd21313123123/radar-cs`. Следующие изменения отправляй в `main` через `git push`. Если нужен **публичный** репозиторий, запусти из CMD `publish_to_github.bat -Public`. Не передавай токен GitHub в чат или в ZIP.

После успешной первой сборки на сервере GitHub в `Releases` появятся **EXE, полный ZIP и SHA-256**. Для каждого нового `push` в `main` создаётся новый предварительный релиз `build-N`. Для стабильного релиза можно создать и отправить тег (например, `v1.0.0`) — такой релиз будет опубликован без пометки prerelease.

```powershell
# Внутри уже опубликованного репозитория, после подтверждения сборки:
git tag v1.0.0
git push origin v1.0.0
```

Сборка происходит на **GitHub-hosted Windows 2022** с предустановленным MSVC `link.exe`, запускает `cargo test` и `cargo build --release`, затем публикует артефакты. Ветви Pull Request только проверяются, релизы из PR не публикуются. Если компиляция завершается ошибкой, релиз не создаётся — нужно исправить показанные в Actions ошибки.

Автосборка проверяет исходники на минимальном Rust 1.85, сценарии браузерной карты в Chromium, Windows EXE и нативную мини-карту. Публикация выполняется после успешного завершения всех проверок. Версии зависимостей зафиксированы в `Cargo.lock`.

## Запуск на Windows 10/11 x64

1. Установите **Rust x64 1.85 или новее (stable)** с https://rustup.rs и проверьте `cargo --version` в новой консоли.
2. Распакуйте архив и откройте папку `CAS_External_Radar_Rust`.
3. Запустите **`build_windows.bat`** для компиляции, затем **`start_windows.bat`**. Второй файл также сам вызывает `cargo run --release`, если исполняемого файла ещё нет.
4. Запустите CS2 и зайдите на сервер. Браузер откроется по локальной ссылке с временным секретным токеном. При первой установке конфигурации GSI перезапустите CS2 один раз.

**Впервые нужен интернет** для загрузки Rust-зависимостей, офсетов cs2-dumper и карт. В офлайне используйте `--offline` после заполнения `cache/`.

Офсеты загружаются из одного коммита cs2-dumper и сохраняются целиком в `cache/schema-bundle.json`. Если обновление неполное, используется предыдущий полный набор. После обновления со старой версии один раз запустите радар с интернетом: отдельные старые `offsets.json`, `client_dll.json` и `info.json` не гарантируют совместимость между собой и больше не объединяются. Для переноса офлайн-кэша скопируйте `schema-bundle.json` целиком.

Если данные не обновляются более двух секунд, обе карты скрывают старые маркеры и показывают предупреждение. Браузер повторяет запросы после тайм-аута и автоматически возвращается к свежим данным.

Проверить внешний вид без установленной CS2 можно на любой системе, где установлен Rust:

```sh
cargo run --release -- --demo
```

Запустить основной режим:

```sh
cargo run --release
```

Просмотр с телефона в доверенной локальной сети:

```sh
cargo run --release -- --lan
```

Другие опции: `--port 8765`, `--offline`, `--refresh`, `--no-browser`, `--cs2-cfg "D:\\SteamLibrary\\steamapps\\common\\Counter-Strike Global Offensive\\game\\csgo\\cfg"`, `--no-gsi-install`.

**Не публикуйте ссылку с токеном и не делайте проброс порта** на роутере: при `--lan` используется HTTP без TLS. На телефоне замените `127.0.0.1` на локальный IPv4 ПК, оставив полный `?token=...`.

## v1.10 — звуковые волны и подробные настройки мини-карты

- Вместо постоянного круга от скорости отображаются отдельные звуковые импульсы. Шаги определяются по игровым сигналам; ходьба с Shift, приседание, воздух и простая смена оружия не создают ложный шум.
- Каждая волна расширяется и затухает в месте звука. Радиус берётся из игровых аудиопрофилей: шаги — до 1100 единиц (около 28 м), глушитель — до 1400 (около 36 м). Для дальних выстрелов показывается верхняя граница. Стены и перекрытия не моделируются; источники и ограничения описаны в `assets/sound_profiles.md`.
- Откройте **Настройки → Мини-карта → Игроки и подписи**: отдельно включаются число и полоска ХП, иконка и название оружия, никнеймы, броня, шлем, стрелки высоты, ослепление, союзники, противники и свой персонаж. Настраиваются размер маркеров, шрифт и цвета. Доступны режимы «Компактно» и «Подробно».
- В **Бомба и гранаты** выбираются маркеры, зоны, траектории и таймеры. В **Окно и камера** — поведение окна, масштаб и прозрачность.
- В **Настройки → Звук** отдельно для основной карты и мини-карты выбираются видимость, анимация, цвет, яркость и отображение радиуса в метрах. Основная карта учитывает системное уменьшение анимации.
- Настройки применяются сразу. Мини-карта сохраняет их в `cache/overlay_settings.json`, веб-карта — в браузере. «Сбросить раздел» восстанавливает только выбранную группу; старые настройки совместимы.

## v1.9 — исправления C4, таймера и трассеров

- Увеличена панель C4 на нативной миникарте (241×91) и на веб-карте (232×96); минимальный размер окна миникарты теперь 295×205, чтобы цифры не обрезались. В панели только плэнт A/B и крупное число секунд, **строка ХП удалена полностью**.
- C4 на земле проверяется не только по item definition 49, но и по имени сущности Source 2; состояния `m_bBombDropped` в GameRules помогает избежать устаревшего владельца после сброса. При отсутствии настоящих координат бомба не рисуется в случайной точке.
- Исторические точки полёта гранаты теперь дополняются реальными снимками вместо перезаписи уже накопленной линии пустой историей. Добавлены диагностические счётчики по каждому типу.
- Большая карта реагирует на изменение размеров контейнера через ResizeObserver; после загрузки изображения принудительно обновляет графику.
- Исправлена причина несовпадения версий веб-карты: сервер теперь всегда отдаёт встроенный в EXE `web/index.html`. Старый HTML из распакованной папки больше не перекрывает свежий интерфейс. Для разработчиков доступен явный флаг окружения `CAS_RADAR_DEV_WEB=1`. Если изображение не доступно, сохраняется сетка с сообщением о проблеме, вместо полностью пустого поля.
- Поддерживаются все предыдущие функции, переключатели таймера и трассеров. Сборка и модульные тесты запускаются на GitHub Actions.

## v1.8 — компактный таймер C4 на обеих картах

- После подтверждённой установки C4 появляется компактная тёмная панель по образцу скриншота: круговое бирюзовое кольцо, площадка A/B, ХП наблюдаемого игрока и время до детонации с десятыми. В последние 10 секунд кольцо оранжевое, в последние 5 красное.
- Источник времени: `C_PlantedC4.m_flC4Blow` и `m_flTimerLength` относительно клиентского игрового времени `dwGlobalVars + 0x30`. Это не 40-секундный отсчёт от момента появления бомбы в радаре. Если одно из полей не читается, вместо ложного таймера панель не показывается.
- Поле `m_nBombSite` определяет A/B; неизвестный сайт помечается знаком вопроса. Строка **ХП** — фактическое здоровье локального игрока или наблюдаемого в спектаторе, **не прогноз урона от C4**, который зависит от укрытий и стен.
- Отсчёт доступен отдельно в большой веб-карте и в отдельной Windows-мини-карте. Опции «Таймер C4 на большой карте» и «Таймер C4 на миникарте» выключаются независимо. Настройки сохраняются, по умолчанию обе включены.
- Отсчёт скрывается после взрыва, успешного разминирования, отсутствия подтверждённых данных или при достижении нуля. При кратковременных пропусках положение панели не сохраняется как выдуманное время.
- Тесты на корректность остатка, A/B, невалидное время и переключатель окна.

- Красный маркер установленной C4 остаётся прежним. Новые пути — фактические наблюдаемые участки, не физическая экстраполяция через стены; если клиент не реплицирует гранату, отследить её невозможно.

## v1.6 — автоматическое следование за спектатором

- Когда локальный игрок жив, мини-радар следует за ним. После смерти, в режиме наблюдения за союзником/другим игроком, берутся позиция и yaw наблюдаемой цели из `CCSPlayerController.m_hObserverPawn` → `C_BasePlayerPawn.m_pObserverServices` → `CPlayer_ObserverServices.m_hObserverTarget` (режимы 4/5).
- Реальная цель выбирается по игровому entity handle: при переключении спектатор-кнопками между игроками центр и поворот обновляются автоматически. При смене цели сглаживание угла сбрасывается, чтобы не вращать карту от угла предыдущего игрока.
- Тот же переключатель «Я в центре карты» управляет центровкой. Новая настройка **«Следовать за игроком в спектаторе»** включена по умолчанию; её можно отключить. При свободной камере / невалидной цели мини-радар использует общий центр карты, без случайного наведения на другого игрока.
- В заголовке нативного окна показывается `OBS: <имя>`, если данные наблюдаемой цели подтвердились. Не требуется менять браузерный радар.
- Добавлены тесты переключения цели, freecam, приоритета локального игрока и сохранения настройки.
- Источник данных: текущая client.dll схема `cs2-dumper`; при обновлении CS2 схемы загружаются из уже существующего механизма `assets`.

## v1.5 — зоны смоков и молотовых, траектории гранат

- Два радара показывают площадь действия смока (приблизительный круг 160 игровых единиц) и молотова (общий радиус плюс положения активных ячеек огня).
- После броска отображается пунктир уже пройденной траектории. Используются исторические точки из Source 2, если читаются, иначе реальные позиции, накопленные между снимками. Это не прогноз будущих отскоков.

- Внешнее чтение памяти CS2 использует классы C_SmokeGrenadeProjectile, C_MolotovProjectile и C_Inferno. Зоны рисуются только если сущности реплицированы клиенту. Площадь смока объёмная, а 2D-круг условный; площадь молотова зависит от ячеек горения и поверхности.
- Путь обновляется при чтении подробных игровых данных (~280 мс), а не предсказывается физическим симулятором.

## v1.4 — бомба на земле, переносимая C4

- **Сканирование сущностей C4:** кроме dwWeaponC4 (который может быть локальным указателем), ридер проверяет доступные weapon-entity в списке объектов CS2 и ищет item definition 49. Затем считывает `C_BaseEntity.m_hOwnerEntity` и сопоставляет владельца с текущим pawn террориста. C4 остаётся отмеченной при переключении на другое оружие.
- **Сброшенная C4:** когда найден настоящий объект C4 с отсутствующим владельцем, считываются `CGameSceneNode.m_vecAbsOrigin` или `C_C4.m_vecLastValidDroppedPosition`. На веб- и нативной миникарте появляется жёлтый маркер бомбы. При подтверждённой установленной бомбе — красный маркер. Если клиент не получает координаты C4, метка не выдумывается.
- **Нет мерцания:** последняя подтверждённая координата может сохраняться до 1,4 секунды при неполном чтении; после появления другого владельца метка на земле исчезает. Старый носитель не остаётся помеченным после уверенного обнаружения сброшенной бомбы.
- **Диагностика:** добавлены счётчики сканируемых сущностей C4 и найденного мирового объекта.
- **Тесты:** новые проверки переходов «в руках → сброс → поднята», исчезновения устаревшей позиции и приоритета позиции на земле.
- **Важно:** отображение удалённой C4 зависит от сетевой репликации игры; если C4 не присутствует в памяти клиента, отображение не гарантировано. Сканирование выполняется на цикле детальных данных, а не каждый кадр отрисовки.

## Нативный мини-радар Windows (v1.0)

1. Откройте обычный веб-радар, нажмите в верхней панели **▣ MINI** (или **⚙ COLORS** — внизу откроется та же секция «Мини-радар Windows»).
2. Включите **«Открыть отдельное окно»**. Rust на том же компьютере покажет отдельное системное окно `CAS Radar - Mini Map` с **только картой и маркерами**. Окно не зависит от браузера: браузер можно свернуть или закрыть, пока запущен сервер Rust.
3. Переместите окно за обычный заголовок Windows, потяните за угол/край для изменения размера; настройки масштаба, прозрачности и закрепления игрока доступны на сайте. Кнопка крестика **скрывает окно**, а не выключает весь радар.
4. **«Я в центре карты»** — следование за местоположением локального персонажа: собственный маркер остаётся ровно в центре при перемещении и изменении размера, а изображение карты сдвигается. Когда координат локального персонажа нет, показывается центр обзорной карты без выдуманных данных.
5. **«Поверх всех окон»** использует `HWND_TOPMOST`. Это работает с обычными и большинством безрамочных полноэкранных окон Windows. **Режим эксклюзивного полноэкранного вывода** может скрывать любой стандартный topmost-оверлей — при необходимости переключите CS2 в безрамочный режим.
6. Колесо мыши над мини-радаром изменяет масштаб; в самом окне доступны `C` (включить/выключить следование за собой), `T` (включить/выключить topmost), `+`/`-` (масштаб). Набор цветов игроков синхронизируется из веб-настроек.

Настройки мини-радара хранятся в `cache/overlay_settings.json`, проверяются перед применением и восстанавливаются после перезапуска Rust. Вне Windows кнопки не открывают отдельное окно, и API возвращает `supported:false`. Никакого Edge/Chromium/WebView в этом окне нет: карта декодируется встроенной Windows GDI+, а весь UI окна рисуется средствами Windows. Основной браузерный интерфейс по-прежнему доступен.

### HTTP API мини-радара

- `GET /api/overlay?token=...` — состояние нативного окна и настройки.
- `POST /api/overlay?token=...` с `Content-Type: application/json` — изменить часть настроек. Поля: `visible` (bool), `topmost` (bool), `center_local` (bool), `zoom` (0.7–4.0), `opacity` (50–100), `friend_color`/`enemy_color`/`self_color` (строки `#RRGGBB`). Всё проверяется на Rust-стороне. POST отклоняется без токена, с неправильным типом данных или слишком большим телом.

В браузере запросы выполняются автоматически — вручную API вызывать не нужно.

### Ограничения и проверка

Проведены браузерные тесты управления настройками мини-радара (1440×900 и 390×844), JavaScript проверен через Node. В Linux выполняются тесты и проверка Windows-кода компилятором. GitHub Actions собирает Windows EXE и запускает отдельную проверку нативного окна. Чтение данных живого матча проверяется на компьютере с Windows и CS2.

## Перенесённые модули

| Rust-файл | Назначение |
|---|---|
| `src/overlay.rs` | нативное Win32/GDI+ окно мини-радара, управление topmost/resize/масштабом/центровкой игрока и интеграция с браузером |
| `src/process.rs` | Win32 `OpenProcess`, `ReadProcessMemory`, Toolhelp — только чтение |
| `src/schema.rs` | офсеты и наследование полей схемы Source 2 |
| `src/game.rs` | внешний ридер entity/controller/pawn, команды, HP, оружие, инвентарь, координаты, C4 |
| `src/tracker.rs` | носитель C4, задержка сброса при ошибке чтения, смена карты |
| `src/gsi.rs` | штатный Game State Integration и безопасное определение карты |
| `src/assets.rs` | карты, изображения, кэш JSON, загрузка офсетов |
| `src/server.rs` | локальный HTTP: `/`, `/api/state`, `/api/maps`, `/api/map-image`, `/api/overlay`, `/gsi` |
| `src/state.rs` | синхронизация состояний и приоритет GSI |
| `src/model.rs` | JSON-модели игрока, статус, демоданные, диагностика |
| `web/index.html` | существующий адаптивный интерфейс (HTML/CSS/JS) |

Встроенный HTTP-сервер работает на стандартном `TcpListener`, без Python/Flask/FastAPI и не загружает код в игру. Поддерживается целевой цикл опроса ~60 Гц, частота HTML Canvas независимо стремится к 60 FPS, фактическая частота чтения отображается отдельно.

### C4 и переключение оружия

Смена активного `m_hActiveWeapon` не сбрасывает C4: ридер отдельно проверяет весь `m_hMyWeapons` (item definition `49`), а при наличии `dwWeaponC4` — глобальную сущность и её владельца. Отсутствующая/неполная выборка означает **неизвестно**, а не «бомбы нет». `BombTracker` хранит последнего подтверждённого живого носителя до 8 секунд при неподтверждённых чтениях, с 900 мс допуска для подтверждённого отрицательного инвентаря; смена карты и установленная/не принадлежащая игроку бомба снимают метку. UI использует `bomb_carrier_source=recent` для `C4?`.

### Ограничения

- Код компилируется **на Windows x64** с Rust Stable; на Linux работает только `--demo`.
- Схема Source 2 зависит от версии CS2. Офсеты скачиваются с a2x/cs2-dumper и при недоступности могут использоваться локально закэшированные значения.
- Отдельный внешний процесс **не гарантирует** безопасность от VAC или правил серверов.
- Неотправленные клиенту игровые данные нельзя получить чтением памяти этого клиента; удалённые противники могут отсутствовать.
- Rust-порт основан на исходном архиве v0.8, обновлён в v1.0. **Сборка и автоматические проверки не подтверждают работу со всеми версиями CS2 в живом матче.** При обновлениях игры могут потребоваться новые офсеты и schema.

## Автоматические проверки Windows

Автосборка запускает модульные тесты и `scripts/windows-smoke.ps1`: готовый EXE
в деморежиме, API, авторизацию, выбор Nuke, открытие безрамочной мини-карты,
декодирование/отрисовку локального PNG, закрытие, сохранение и повторное открытие.
Это проверка приложения и окна; она не заменяет проверку чтения в живом матче CS2.

## Тестирование

На компьютере с Rust:

```sh
cargo test
cargo build --release
```

В проекте также есть `.github/workflows/windows-build.yml`: после каждого push в `main` он собирает Windows x64, сохраняет ZIP в Actions и публикует EXE и ZIP в Releases. Публикация выполняется только после успешных тестов, сборки и Windows smoke test.

Исключительно локальное использование. Сервер по умолчанию слушает `127.0.0.1`. GSI принимает запросы только с локального интерфейса и проверяет отдельный долговременный токен. GSI-конфиг не изменяет остальные настройки CS2.
